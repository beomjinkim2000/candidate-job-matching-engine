# candidate-job-matching-engine

# 0. 한문장
- 채용공고 이미지 한 장에서 지원자 랭킹까지 가는데 모든 점수가 '공고 그림의 어느 좌표에서 나온 조건인가'와 '이력서 원문의 어느구간을 근거로 삼았는가'까지 되짚어준다.

# 1. 전체 흐름

## 1. 공고 이미지 확보

<details>
<summary>더보기</summary>

  - 이미지를 sha256만 기록 → 실행 시 받아서 대조
  - 고객사가 원래 가지고있던 이미지의 해시가 받은 이미지와 다르면 저장하지 않음 (좌표는 특정 그림 위에서만 유효하므로)

</details>

## 2. 줄과 좌표 읽기

<details>
<summary>더보기</summary>

  - model : PaddleOCR (lang="korean")
  - 결과 : 평균 신뢰도 0.936
  - 이미지를 LLM에 보내지 않음(VLM은 좌표를 지어내기도하고 당장 VLM을 쓰려면 크레딧으로 했어야했는데 비용문제도 있어서)

</details>

## 3. 섹션·항목 나누기 (코드, 위에서부터 결론 나면 멈춤)

<details>
<summary>더보기</summary>

  - 첫 글자가 불릿 : 항목
  - 불릿 없이 직전 항목보다 4~60px 더 들여씀 : 이어지는 줄 (앞 항목에 병합)
  - x0 < 100 : 섹션 제목
  - 그 외 : 그다음 스텝에서 LLM이 헤더로 승격 안 되면 버림
  - 실측 : 섹션 29 / 항목 22 / 애매 10 / 이어지는 줄 4

</details>

## 4. 헤더 역할 분류 (LLM 사용)

<details>
<summary>더보기</summary>

  - 3번에서 섹션이 나눠지지 않은 부분은 사전을 쓰지 않고 역할을 나눈다. 나누는 항목은 총 5가지.
    - requirement : 나누는 조건
    - preferred : 있으면 좋은 조건
    - duty : 입사 후 할일
    - context : 회사,팀 소개 (채점에 사용x)
    - excluded : 복리후생, 전형절차, 문의 (채점에 사용x)

</details>

## 5. 필수/우대 판정 (사다리 5단) (E2=공고에 명시됨, E1=공고 구조에서 추론, E0=아무런 신호가 없을때)

<details>
<summary>더보기</summary>

  - 섹션이 requirement : 필수 -> E2
  - 섹션이 preferred : 우대 -> E2
  - 항목에 '필수','반드시' : 필수 -> E2
  - 항목에 '우대','있으면' : 우대 -> E2
  - 담당 업무와 낱말이 두개이상 겹침 : 필수 -> E1
  - 같은 조건이 2회 이상 나옴 : 필수 -> E1
  - 아무 신호 없음 : 우대 -> E0 (근거 없이 필수로 두면 배점 14.29가 걸리므로 약한 쪽으로)
  - LLM에 안맡김. 배점을 3:2로 가르는 값이라 흔들리면 안됨

</details>

## 6. 조건 갈래 분류 (LLM) (조건 내용이 아니라 '이력서에서 어떻게 확인되나'만 물음)

<details>
<summary>더보기</summary>

  - 사실층 : 코드가 문자열 대조. 같은 입력이면 항상 같은 점수
  - 판단층 : 심사위원 LLM이 읽고 1~5점. 실행마다 흔들릴 수 있음..

---

  - term : 도구,기술 이름이 있어서 이력서에 같은 말이 있는지 찾음 -> 사실층
  - binary : 예/아니오인데 이력서에는 다른 말로 적을 때 -> 판단층 (충족형 기준)
  - graded : 잘하고 못하고의 정도가 있을 때 -> 판단층 (정도형 기준)
  - LLM 실패시 폴백 : 숫자·라틴문자 있으면 term, 아니면 graded

</details>

## 7. 루브릭 생성

<details>
<summary>더보기</summary>

  - 채점 항목 = 공고 조건 항목의 문구(헤더 밑에 섹션 본문) 그대로 감. 항목 목록을 코드에 안 박음
  - 점수 기준 = 공고 조건 문구 + 코드에 고정된 판정 문구 (1/3/5점)
  - 2점,4점은 비움. 5개를 어중간하게 쓰느니 3개를 잘 쓰는 쪽
  - 판정 문구는 2벌뿐 : 정도형(term,graded) / 충족형(binary)
  - 배점 = 필수3 : 우대2 : 담당업무1 비율로 조건 개수에서 계산
    - 예) 필수4,우대2,담당5 -> 총가중치 21 -> 14.29 / 9.52 / 4.76점
  - (밑에는 예시, 항목별 판정 문구는 고정)
  - 정도형
    - 1점  B2C고객을위한 상품마케팅및세일즈기획 — 관련 경험이 없거나, 있어도 구체적 행동 서술이 없음
    - 3점  B2C고객을위한 상품마케팅및세일즈기획 — 제시하나 서술이 추상적이고 본인 역할,성과가 불명확함
    - 5점  B2C고객을위한 상품마케팅및세일즈기획 — 본인의 역할,취한 행동,달성한 성과가 명확히 서술됨
  - 충족형
   - 1점 서로다른이해관계를조율하며… — 관련 경험이 없거나, 있어도 구체적 행동 서술이 없음
   - 3점 서로다른이해관계를조율하며… — 제시하나 서술이 추상적이고 본인 역할,성과가 불명확함
   - 5점 서로다른이해관계를조율하며… — 본인의 역할,취한 행동,달성한 성과가 명확히 서술됨

</details>

## 8. 루브릭 사람 승인 (여기서 파이프라인이 실제로 멈춤)

<details>
<summary>더보기</summary>

  - prepare()는 이력서를 아예 안 받음. score()는 승인 없으면 예외
  - 할 수 있는 것 3가지 : 승인 / 필수<->우대 뒤집기 / 삭제
  - 가중치는 못 만짐. 열면 직군 무관 일반화가 무너짐
  - 건너뛰면 결과와 화면에 '미승인' 표시가 붙음

</details>

9. 채점 (3층)
  - 0층 게이트 : 면허,법정 자격증만. 통과/탈락
  - 1층 사실채점 : 코드. 결정적
  - 2층 판단채점 : 심사위원 2명 독립 채점 -> 평균. 2점 이상 갈리면 3번째 호출
  - 배점 판단 65 : 사실 35 (세는 방식 r≈0.15, 판단 방식 r≈0.48)
  - 한쪽 층에 항목이 없으면 있는 층이 100점을 다 가져감
  - 마스킹 : 이름,성별,나이,출신지,학교를 ■로. 길이 보존(오프셋이 밀리면 근거가 어긋남)

10. 검산 G1~G7 (테스트가 아니라 돌 때마다 도는 게이트. 하나라도 걸리면 결과 안 나감)
  - G1 : 모든 점수에 근거 링크
  - G2 : 모든 인용이 이력서 원문과 글자까지 일치 (지어낸 인용 차단)
  - G3 : 모든 채점 항목에 대응 조건 존재
  - G4 : 모든 조건에 이미지 좌표 존재 -> '원문 복붙 안 함'의 기계적 증명
  - G5 : 모든 조건에 근거 등급 존재
  - G6 : 이력서의 모든 주장이 채택/배척/무관 중 하나
  - G7 : 승인이 현재 공고 버전에 대한 것

11. 합산,랭킹
  - 환산 = 배점 × (원점수 - 1) ÷ 4
  - 1점이 0점. 1점은 '없다'는 뜻이라 점수를 주면 미스매칭에게도 바닥이 깔림
  - 결과 : 완벽 94.44 / 91.67, 부분 58.93 / 57.74 / 54.76, 미스 38.10
