| 순 | 케이스 | 어느 step에서 만들었나 | 이 step에서 할 일 | 임계 |

| 1차 | 스코어러 경계 | step 5 | 확인만 | 정확 일치 |

| 2차 | **홀드아웃 조건** | — | **여기서 작성 (신규)** | `sd > 2σ` (raw 1~5) |
| 2차 | 게이트 정확성 | step 5 | 확인만 | 정확 일치 |

**반복 안정성만 「마크 확인」이 아니다.** 홀드아웃 테스트가 그 σ를 노이즈 기준선으로
쓰기 때문이다 — 안 돌리면 홀드아웃이 skip되고, **1차/2차를 통틀어 라벨 밖 측정 지점이
직군 교차 하나만 남는다.**

```bash
pytest tests/test_judge.py -m live -k repeat_stability -q   # 44회 호출. 완주 예산 밖
```

**σ의 저장 주소는 `index.json`의 step 6 `summary`, 키는 `repeat_sigma` 하나다.**
step 6이 그 측정을 소유하므로 그 자리에 적는다 (`step6.md`). 이 step은 **읽기만** 한다 —
두 곳에 적으면 홀드아웃 테스트가 어느 쪽을 볼지 모르고, 못 찾으면 조용히 skip된다.

### `tests/test_holdout.py` — 라벨이 안 건드린 지점 (신규)

```python
HOLDOUT_K = 2.0   # 임의값

def test_holdout_criteria_discriminate(repeat_sigma):
    """이력서 설계에서 제외한 조건 2개에서도 지원자별 점수가 갈리는가.

    **양변 모두 1~5 raw 척도다.** 가중 점수(0~100)로 재면 임계가 무의미해진다.
    repeat_sigma: index.json의 step 6 summary["repeat_sigma"]. 없으면 이 테스트는 skip.
                  상위 2명 × 판단항목 2개에서 잰 합동 표준편차이고, 6명 × 홀드아웃
                  2조건에 적용하는 것은 근사다 (step6.md).
    """
    if repeat_sigma is None:
        pytest.skip("step 6의 반복 안정성 σ 실측이 없다 — 노이즈 기준선 없이 판정하지 않는다")

    # Score.value 중 layer=='judgment' 인 raw 1~5 값. weight를 곱하기 전이다.
    raw = [raw_scores(c, holdout_criteria) for c in candidates]   # 6명
    sd_holdout = stdev([mean(r) for r in raw])
    assert sd_holdout > HOLDOUT_K * repeat_sigma, (sd_holdout, repeat_sigma)
```

`data/resumes/{posting_id}/holdout.json`이 가리키는 조건 2개만 골라 6명의 **raw 점수(1~5)**
표준편차를 구하고, **채점 노이즈 σ의 2배를 넘는지** 본다.

> **「분산 > 0」에서 바꿨다 (R3 심사).** 우리가 인용한 실측이 「같은 질문 50회 반복 시
> 판정 13.6% 뒤집힘」이고 허용 흔들림이 σ≤0.5다. **그 노이즈만으로 6명의 분산은 거의
> 확실히 0을 넘는다** — 「분산 > 0」은 엔진이 홀드아웃 조건을 **전혀 변별하지 못해도 통과**했다.
>
> **척도를 못박았다 (R4 심사).** `sd_noise`는 `step6.md`에서 **5점 척도**로 정의됐는데
> 좌변의 척도가 안 적혀 있었다. 가중 점수(0~100)로 재면 **엔진이 아무것도 변별하지 못해도
> 통과**한다 — 척도가 다른 두 수를 2배로 비교하는 자리였다. **양변 모두 raw 1~5**다.
>
> **σ가 없으면 통과시키지 않고 skip한다 (R4 심사).** 이전 판은 fallback 0.5를 썼는데,
> 그 0.5는 **임계값**이지 **실측 노이즈**가 아니다. 임계를 노이즈 추정치 자리에 넣으면
> 그 비교는 아무 말도 안 한다. **기준선이 없으면 판정하지 않는다.**
>
> `HOLDOUT_K = 2.0`은 **임의값**이다.

**이 테스트가 돌려면 step 6의 `@live` 반복 안정성이 실제로 한 번 실행돼야 한다.**
아래 「케이스 점검표」의 「마크 확인」으로는 부족하다 — 그래서 이 step의 검증 절차에
**실행 1회**를 넣었다.

**이 테스트가 무엇을 말하는가**: 우리가 「이 사람은 완벽 매칭」이라고 정하며 손대지 **않은**
조건에서도 엔진이 사람마다 다른 점수를 낸다면, 그 차이는 **우리 라벨이 만든 게 아니다.**
분산이 0이면 반대다 — 엔진이 우리가 설계한 축에서만 작동한다는 뜻이고, 그건 일반화가
아니라 **우리 데이터에 맞춘 것**이다.

**이 테스트는 순환을 끊지 못한다.** 이력서 전체는 여전히 조건을 보고 썼다.
**측정 지점 하나가 라벨 밖에 있을 뿐**이고, 그 한계를 `summary`에 적는다.

### `tests/test_generalization.py` — 직군 교차 (핵심)

```python
def test_cross_job_rubric_penalizes():
    """공고 A의 루브릭으로 공고 B의 지원자를 채점하면 점수가 떨어져야 한다."""
```

공고 A의 완벽 매칭 지원자를 **공고 B의 루브릭**으로 채점하고, 원래 점수보다 유의하게
낮은지 확인한다.

**이 테스트가 왜 가장 값진가**: 과제 CRITICAL이 "직군 무관 일반화"인데, 그건 보통 말로만
주장된다. 이 테스트는 그 주장을 **반증 가능한 형태**로 만든다. 루브릭이 정말 공고에서
생성됐다면 다른 공고의 루브릭은 안 맞아야 한다. 점수가 안 떨어지면 **루브릭이 사실상
직군 무관하게 작동하지 않는다는 뜻**이다.

### `tests/test_verbosity.py` — 장황함 불변성

같은 내용을 길게 쓴 이력서와 짧게 쓴 이력서를 만들어 점수 차가 임계값 이내인지 본다.

```python
LONG = "..."   # 짧은 버전과 사실 내용은 동일, 서술만 길게
SHORT = "..."
def test_verbosity_invariance():
    assert abs(score(LONG) - score(SHORT)) <= THRESHOLD
```

**이건 `@pytest.mark.live`다** — 심사위원 픽스처로는 검증이 안 된다. 기본 실행에서 빠진다.

**임계값은 만점의 10%로 고정한다. 임의값이고, 실측으로 고치지 않는다.**
실제로 돌려본 값은 주석과 `summary`에 남긴다 —
"임계값을 통과했다"보다 **"실측이 얼마였다"**가 더 정직하다.

**기록 시각: 2026-09-01 12:30** — 이 step을 완료하며 `index.json` step 11의 `summary`에
**실측치를 적는다. 임계는 고치지 않는다.**

> **「실측으로 임계를 고친다」를 취소했다 (R3 심사 지적).** 그건 **판정선을 판정 대상의
> 실행 결과에서 뽑는 것**이다 — 그러면 테스트는 무엇도 반증하지 못한다. 같은 문서의
> `step12.md`·`tests/CLAUDE.md`는 정반대 규칙(「한 번의 실측으로 임계를 옮기지 않는다」)을
> 적고 있었고, 이 줄만 어긋나 있었다.
>
> **오늘 하는 것은 숫자를 적는 것까지**다. 임계 조정은 `docs/OPERATIONS.md`의
> 「다음 사람이 할 일」로 넘긴다 (`step13.md`).

```bash
ruff check tests
pytest -q                          # live 제외 (pyproject의 addopts)
pytest -q -m live --collect-only   # 나머지 live 케이스는 수집만 확인

# 반복 안정성만 실제로 1회 돌린다 — 44회 호출. 완주 예산(≈117회) 밖이다.
# 홀드아웃 테스트가 이 σ를 노이즈 기준선으로 쓰므로, 안 돌리면 그 테스트가 skip된다.
pytest -q -m live -k repeat_stability tests/test_judge.py

# σ가 실제로 저장됐는지 확인하고, 그 값으로 홀드아웃을 돌린다
python3 -c "
import json,pathlib
d=json.loads(pathlib.Path('phases/matching-engine/index.json').read_text())
s6=next(s for s in d['steps'] if s['step']==6)
sig=(s6.get('summary_data') or {}).get('repeat_sigma')
assert sig is not None, 'step 6 summary에 repeat_sigma가 없다 — 홀드아웃이 skip된다'
print('repeat_sigma =', sig)
"
pytest -q tests/test_holdout.py
```

**`--collect-only`로는 부족한 케이스가 하나 있다.** 반복 안정성은 다른 테스트의 **입력**을
만든다 — 수집만 확인하면 σ가 안 생기고, 홀드아웃이 조용히 skip되며, **라벨 밖 측정 지점이
직군 교차 하나만 남는다.** 그래서 이 하나만 실제로 돌린다.

**44회 호출은 완주 예산 밖이다** (`docs/COST_BUDGET.md` §1은 ≈117회를 센다).
예산이 모자라면 **이 테스트를 버리고, 버렸다는 사실과 그때 홀드아웃이 skip된다는 사실을
`summary`에 적는다.** N을 줄이지 마라 — 11은 인용된 실측이다.

**로컬에서 `pytest -q`를 반복 실행하지 마라.** 전체 검증은 push 후 CI에 맡긴다
(`CLAUDE.md` 작업 규칙).
