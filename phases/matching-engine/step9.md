### 첫 화면 — 무엇을 해야 하는지가 화면에 있어야 한다

**결과가 이미 있는 상태에서 시작하는 목업은 첫 화면이 아니다.** 브라우저를 열었을 때
데이터가 하나도 없는 상태가 실제 첫 화면이고, 거기서 무엇을 누르는지가 정해져 있어야 한다.

```
┌─ 0. 시작 화면 (결과 없음) ──────────────────────┐
│  공고를 고르세요                                 │
│   ○ KT — B2C마케팅&세일즈        [데모 데이터]       │
│   ○ 넥슨 — 게임 프로그래머    [데모 데이터]       │
│                                                 │
│   지원자 6명이 함께 채점됩니다                    │
│   예상 호출 ~59회 · 소요 2~4분                   │
│                       [ 조건 확인하기 → ]        │
└─────────────────────────────────────────────────┘
        ↓ POST /prepare (채점 안 함)
┌─ 0.5 승인 화면 ─────────────────────────────────┐
│  공고에서 뽑은 조건 n개 — 전부 [AI 초안]          │
│  각 조건마다: [승인] [필수↔우대 뒤집기] [삭제]     │
│  조건을 클릭하면 공고 이미지의 그 위치에 네모      │
│                       [ 승인하고 채점 → ]         │
└─────────────────────────────────────────────────┘
        ↓ POST /approve → POST /score
┌─ 1~3. 결과 화면 (아래) ─────────────────────────┐
```

**승인 화면이 없으면 「사람 확인함」 배지가 절대 안 나온다.** 배지를 화면에 두면서
그 값이 될 경로를 안 만들면, 그 배지는 장식이고 화면이 거짓말을 한다.
백엔드는 `step8.md`의 `POST /prepare` · `POST /approve`가 이미 담당한다.

**「예상 호출 ~59회」는 실측으로 대체한다** — **2026-09-01 14:30**(step 13, 완주 후)에
`docs/COST_BUDGET.md` §4의 값으로 바꾼다. 담당은 step 13이고 `docs/SCHEDULE.md` §5에
같은 시각이 적혀 있다. **추정치를 화면에 계속 두지 마라.**

### 화면 구성 3단

```
┌─ 1. 루브릭 패널 ────────────────────────────────┐
│  공고에서 뽑은 조건과 그 판정                     │
│  필수  Python 3년 이상        [E2] [사람 확인함]  │
│  필수  대규모 트래픽 처리      [E1] [AI 초안]     │
│  우대  Kubernetes             [E0] [AI 초안]     │
│  → 조건을 클릭하면 공고 이미지의 해당 위치에 네모   │
├─ 2. 랭킹 ──────────────────────────────────────┤
│  1위  지원자 A   82.4                            │
│  2위  지원자 B   79.1                            │
│  ...                                            │
│  ── 게이트 탈락 ──                               │
│      지원자 F   면허 미보유                       │
├─ 3. 상세 (지원자 클릭 시) ───────────────────────┤
│  축별 점수 · 근거 · 근거 클릭 시 이력서 하이라이트  │
└────────────────────────────────────────────────┘
```

### 반드시 들어갈 것

1. **근거 등급 배지** (`E2` / `E1` / `E0`) — 조건마다
2. **검토 상태 배지** (`사람 확인함` / `AI 초안`) — 조건·루브릭 항목마다.
   **두 배지의 생김새를 확실히 다르게** 한다
3. **추적** — 점수를 클릭하면 `trace()`를 따라가
   (a) 이력서 원문의 근거 구간이 하이라이트되고
   (b) 공고 이미지의 해당 bbox에 네모가 쳐진다
4. **마스킹 표시** — 무엇을 가리고 채점했는지 (이름·나이·학교 등)
5. **탈락자 표시** — 숨기지 않고 사유와 함께 목록 끝에
6. **배지의 뜻이 화면 안에 있어야 한다.** `E2`/`E1`/`E0`은 한국어가 아니라 코드다 —
   호버 툴팁이든 범례 한 줄이든, **문서를 열지 않고 화면만 보고 알 수 있어야 한다**.
   `사람 확인함`/`AI 초안`은 그 자체로 읽히므로 추가 설명이 필요 없다
7. **「데모 데이터」 배지** — `PostingRef.source_kind`가 `saramin_api`거나 `local`이면 띄운다.
   프로덕션 경로(`client_feed`)의 결과와 헷갈릴 수 없게 만드는 것이 목적이다
8. **실행 비용** — 「이 결과: n회 호출 · $x · 모델 <이름>」 한 줄. `RunResult.cost`에서 온다
9. **파싱 진단** — `ParseReport`의 `role_counts`·`ambiguous` 비율·`parse_mode`.
   임계값이 공고 1건 실측에서 나온 값이라, 다른 공고에서 빗나갔을 때 이 숫자만 보면 안다

### 배지가 한 줄에 몇 개까지 붙나 — 세어보고 정한다

조건 하나에 최대 **4개**가 붙을 수 있다: 근거 등급 + 검토 상태 + `인용 유효` + `근거 충실도`.
여기에 화면 상단의 「미승인」·「데모 데이터」·「판단 층 생략」까지 더하면 읽히지 않는다.

**규칙**: 조건 행에는 **근거 등급 + 검토 상태 2개까지만** 상시 노출하고,
`인용 유효`·`근거 충실도`는 **상세를 펼쳤을 때만** 보인다. 상단 경고 배지는
**있을 때만** 나오므로 정상 실행에서는 0개다.

### 공고 이미지 bbox 렌더링

이미지를 `<img>`로 놓고 그 위에 `position: absolute`인 `<div>`로 네모를 그린다.

**스케일 기준은 `naturalWidth`가 아니라 `bbox.img_w`다.**

```js
const sx = img.clientWidth / bbox.img_w;   // naturalWidth가 아니다
const sy = img.clientHeight / bbox.img_h;
```

이유: 좌표는 **파싱 당시 본 이미지** 기준이다. 데모(사람인 CDN 사본)와 프로덕션(고객사
원본)은 해상도가 다르므로, 지금 화면에 띄운 이미지가 그때 그 파일이라는 보장이 없다.
`naturalWidth`를 쓰면 **다른 이미지로 결과를 다시 볼 때 네모가 엉뚱한 자리에 그려진다**
(`docs/IMAGE_ACQUISITION.md` §4-②).

`bbox.img_w != img.naturalWidth`면 화면에 **경고를 표시**한다 — 조용히 스케일하지 마라.

### 주의 — 숫자를 화면 중앙에 크게 띄우는 것의 함정

수치 설명은 부당한 신뢰를 만든다는 지적이 있다. 대응:

- 총점 옆에 **항상 축별 분해를 함께** 둔다. 총점만 크게 띄우지 않는다
- 근거 없이 나온 점수는 애초에 검산에서 막히므로 화면에 없다

## Acceptance Criteria

```bash
ruff check src/matching/api
pytest tests/test_api.py -q
python3 -c "
import pathlib, re
h = pathlib.Path('src/matching/api/static/index.html').read_text()

# 1) 오프라인에서 열려야 한다 — 외부 호스트를 부르면 안 된다
ext = [u for u in re.findall(r'https?://[^\"\\'\\s>]+', h) if 'localhost' not in u and '127.0.0.1' not in u]
assert not ext, f'외부 URL {ext[:3]}'

# 2) 배지가 있는 것만으로는 부족하다 — **뜻이 화면에 있어야 한다**
#    R1 지적: assert kw in h 는 문자열이 HTML 안에 있기만 하면 통과한다
for code in ['E2', 'E1', 'E0']:
    assert re.search(rf'(title|aria-label|data-tip)=\"[^\"]*{code}[^\"]*[가-힣]', h), \\
        f'{code}의 뜻이 화면에 없다 (툴팁·범례 어디에도)'
for kw in ['AI 초안', '사람 확인함', '데모 데이터', '미승인']:
    assert kw in h, kw

```

**2번이 R1 지적에 대한 답이다.** 이전 AC(`assert kw in h`)는 `E0`이라는 두 글자가 HTML
어딘가에 있기만 하면 통과했다 — **뜻이 화면에 없어도 검사는 초록이었다.** 이제 `E0` 옆에
한글 설명이 붙은 속성이 있어야 통과한다.

수동 확인: `python run.py`로 띄워 브라우저로 연 뒤 **스크린샷을 남긴다.**
화면 구현은 사용자 담당이므로, 이 step은 **위 AC가 통과하는 최소 화면**까지만 만든다.

## 금지사항

- **React·Vue·번들러를 쓰지 마라.** 이유: 평가자가 `npm install`을 하게 만들면 안 된다.
- CDN 링크를 넣지 마라. 이유: 오프라인에서 화면이 깨진다.
- **근거 등급과 검토 상태를 하나의 배지로 합치지 마라.** 이유: 서로 다른 것을 잰다.
  하나는 "공고에 명시됐나", 하나는 "사람이 확인했나"다.
- 마스킹된 항목(이름·나이·학교)을 화면에 되살리지 마라. 이유: 블라인드 채용 금지 항목이다.
- **`README.md`를 만들지 마라.**
