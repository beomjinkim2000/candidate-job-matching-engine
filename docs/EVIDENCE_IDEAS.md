# 근거 문제의 해법 3가지

과제에서 가장 어려운 요구는 이것이다.

> *"점수의 근거를 **사람이 읽을 수 있는 형태**로 제시"*

지금까지 우리 답은 **"축별 점수 + 이유 문장 + 이력서 원문 인용"**이었다. 이건 평범하고,
더 나쁘게는 **검증할 수 없다.** 아래 세 가지는 리서치 3건(XAI·LLM 근거검증·인접 도메인)에서
골라낸, **이미 채택한 7가지와 겹치지 않는** 해법이다.

세 가지가 서로 다른 축을 친다.

| | 답하는 질문 | 지금 우리 설계가 못 하는 것 |
|---|---|---|
| **1. 판단유탈 대장** | *무엇을 안 봤는가* | 지원자가 쓴 것 중 무시된 것을 셀 수 없다 |
| **2. 근거 소거 재채점** | *그 근거가 진짜 이유인가* | 인용이 진짜여도 점수의 이유인지는 모른다 |
| **3. 등수 뒤집기 최소 편집** | *왜 저 사람이 아니라 이 사람인가* | 카드는 개별인데 결과는 순위다 |

---

## 아이디어 1 — 판단유탈 대장

### 무엇인가

채점을 **반대 방향으로 한 번 더** 한다.

지금 우리 엔진은 공고에서 조건을 뽑고, 조건마다 이력서를 뒤진다. 방향이
**공고 → 이력서**다. 그래서 커버리지도 공고 쪽으로만 잰다 — "조건 5개 중 4개를 봤다".

**지원자가 이력서에 쓴 것 중 무엇을 안 봤는지는 아무도 안 센다.**

그래서 채점 전에 이력서에서 **주장(claim)을 원자 단위로 뽑아 번호를 매긴다.** 채점이
끝나면 모든 주장은 셋 중 하나여야 한다.

| 상태 | 뜻 |
|---|---|
| `채택` | 어느 축에 얼마나 기여했는지 기록됨 |
| `배척` | 봤지만 반영 안 함 + 사유 태그 |
| `무관` | 공고 요건에 대응하는 것이 없음 |

**하나라도 미처리로 남으면 그 지원자의 판정은 "미완성"이 되고 랭킹에 못 올라간다.**
출력에는 `판단유탈률 = 미처리 주장 수 / 추출 주장 수`가 지표로 붙는다.

> [!example] 손으로 따라가기
> 지원자 B의 이력서에서 주장 14개를 뽑았다.
> 채택 6 / 배척 5 / 무관 3 → 미처리 0 → 판단유탈률 0.00 → 랭킹 진입.
>
> 지원자 D는 주장 11개 중 채택 4 / 배척 2 / 무관 2 → **미처리 3** → 판단유탈률 0.27 →
> **랭킹 보류.** 화면에는 "다음 3개 주장이 어느 축에도 걸리지 않았습니다"가 뜬다.

### 어디서 왔나

**법원의 판단유탈(판단누락) 법리**다. 판결 이유에는 당사자 주장에 대한 판단을 표시해야
하고, **주장했는데 판단하지 않은 것 자체가 상고이유**가 된다.

대법원이 둔 완화 조항 두 개가 우리에게 그대로 쓸모 있다.

1. 구체적 판단이 없어도 **이유 전반의 취지로 인용/배척을 알 수 있으면** 판단누락이 아니다
   → 명백히 무관한 주장은 **일괄 사유 태그로 묶어도 된다**
2. 실제로 판단하지 않았어도 **그 주장이 배척될 것이 분명하면** 위법이 아니다
   → 임계값 아래 주장은 자동 `무관` 처리

같은 발상이 학술 피어리뷰에도 있다. ICLR 2026 Area Chair 지침은 메타리뷰에
**"리뷰어가 제기한 쟁점을 나열하고 각각을 어떻게 반영했는지"**를 쓰라고 강제한다.

행정절차법 제23조도 같은 구조다 — **이유 제시 흠결은 그 자체로 취소사유**다. 결론이
옳아도 이유를 안 달면 처분이 취소된다.

### 왜 참신한가

우리가 이미 채택한 것들은 **전부 공고 쪽 커버리지**다. 축별 점수 분해도, evidence span도,
루브릭 항목도 다 "공고가 요구한 것을 봤는가"를 잰다.

**실무에서 지원자가 가장 억울해하는 지점은 정확히 반대쪽**이다 — "내가 쓴 걸 안 읽었다".
루브릭 기반 엔진은 구조적으로 이걸 못 본다. 루브릭에 없는 강점은 존재하지 않는 것과
같기 때문이다.

그리고 이게 **테스트 케이스로 곧바로 이어진다.** 「이력서에만 있고 공고에 대응 요건이 없는
주장」을 넣은 픽스처를 만들어, 판단유탈률이 0이 아닌지 + 그 주장이 `무관` 태그를 받았는지
검사한다. 과제 평가 기준이 *"어떤 케이스를 골랐는지"*이므로 이건 값진 케이스다.

### 비용

주장 추출 LLM 1회 추가 호출(이력서당). 12명이면 12회. 매칭 표시는 기존 채점 프롬프트에
`claim_id` 반환을 추가하면 되므로 **추가 호출 0**. 대장 자체는 자료구조 하나.

### 이 아이디어가 틀리는 조건

- **무관한 주장이 대량이면 지표가 죽는다.** 취미·자기소개 서술이 많으면 판단유탈률이
  노이즈로 채워진다 → 추출 단계에서 "직무 관련성 후보"만 claim으로 승격하는 필터가
  필요한데, **그 필터 자체가 누락의 진짜 원인**이 될 수 있다. 이건 문서에 적어야 한다
- 무기재를 불리로 읽으면 안 된다. `무기재`(언급 자체가 없음)와 `부재 확인`(언급은 있으나
  수준 미달)을 **반드시 구분**한다. 경력 단절·비전형 이력이 구조적으로 손해 보는 걸 막는다

## 아이디어 2 — 근거 소거 재채점 (플라시보 대조군 포함)

### 무엇인가

심사위원이 인용한 문장을 **이력서에서 실제로 지우고 다시 채점한다.** 점수가 안 내려가면
그 인용은 **점수의 이유가 아니라 사후 정당화**다.

여기까지는 알려진 기법이지만, **그냥 하면 반드시 틀린다.** 문서에 구멍을 내는 행위 자체가
점수를 떨어뜨리기 때문이다(짧아진 이력서 = 빈약해 보임). 그래서 **같은 길이의 무관한
문장을 지운 플라시보 조건**을 대조군으로 함께 돌리고, **두 조건의 차이만** 근거의 기여로
인정한다.

그리고 반대쪽 반쪽을 짝으로 붙인다 — **인용 문장만 남긴 축소 이력서로 재채점**해서 원점수가
재현되는지 본다. 재현되지 않으면 **밝히지 않은 이유로 점수를 준 것**이다.

```
항목 r에 대해:
    s_full    = 채점(이력서 전체)
    s_ablate  = 채점(이력서 - 인용 구간)            # 근거 제거
    s_placebo = 채점(이력서 - 같은 길이 무작위 구간)  # 대조군, 3회 평균
    s_only    = 채점(인용 구간만)                   # 근거만

    기여도    = s_placebo - s_ablate
    충분성    = |s_only - s_full|

    기여도 < tau      → "장식용 근거" 표시   # 지워도 점수가 그대로
    충분성 > eps      → "숨은 근거" 표시     # 안 밝힌 이유가 있다
```

이 값을 **근거 충실도**로 각 축 옆에 띄운다.

> [!example] 손으로 따라가기
> 항목 "대규모 트래픽 처리 경험", 5점 만점.
> 전체 이력서로 4.0점. 인용 구간을 지우니 3.8점. 무작위 구간을 지우니 3.9점.
> → 기여도 = 3.9 − 3.8 = **0.1점.** 만점의 2%다.
> **저 인용은 점수를 만들지 않았다.** 근거로 표시하면 안 된다.

### 어디서 왔나

**직접 반증한 실험이 있다.** 루브릭 기반 채점(우리와 설정이 거의 같다)에서, 모델이
스스로 고른 근거 문장과 SHAP이 계산한 실제 기여 문장의 **일치도가 Jaccard 0.085**였다.
전사본당 1~2문장만 겹쳤다는 뜻이다. 삭제 검증에서 LLM 자가 근거의 평균 점수 변화는
0.0033~0.0388로, 무작위 기준선과 거의 구분되지 않았다.

또 하나. 텍스트는 그대로 두고 **비증거 단서(라벨)만** 조작한 실험에서, 거짓 라벨을 주면
심사위원이 판정을 **75~85% 뒤집었고**, 판정이 안 바뀐 경우에도 설명 자체를 새로 썼다
(설명 드리프트 0.75~0.81). 근거를 **먼저 잠그는** 프로토콜을 쓰면 뒤집힘이 5~22%로 떨어졌다.

플라시보 대조군은 문맥 기여도 추정 연구에서 왔다 — 단일 소거가 아니라 **무작위 마스킹
집합**을 써서, 구멍을 내는 행위 자체의 효과를 대조군으로 흡수한다.

### 왜 참신한가

거의 모든 LLM 채점 파이프라인은 근거를 **보여주기만** 하고 검증하지 않는다. 우리가 이미
채택한 "원문 인용 강제"와 "문자열 대조"는 **인용이 원문에 있는가**만 본다.

**그건 다른 질문이다.** 원문에 실재하는 문장을 정확히 인용하면서도 그 문장이 점수와
무관할 수 있다. 채택안 7개 전부가 이 실패를 통과시킨다.

그리고 이건 **과제 평가 기준에 정확히 맞는다.** *"테스트는 커버리지가 아니라 어떤 케이스를
골랐는지"*가 평가 대상이라면, **「근거가 가짜인 경우」를 잡는 테스트**보다 좋은 케이스 선정은
없다.

### 비용

이력서 12개 × 루브릭 5항목 × (1 + 3 + 1) = **약 300회 추가 호출**. 축소 문맥이라 호출당
입력이 1~2k 토큰이다. **전수로 돌리면 예산이 부담되므로 상위 3명 × 전 축으로 표본을
제한**한다 → 약 75회.

### 이 아이디어가 틀리는 조건

- **점수가 이산적이면 무너진다.** 우리 척도가 1/3/5점이라 작은 기여가 Δ=0으로 묻혀
  진짜 근거가 "장식"으로 오판된다 → **재채점 때만 0~100 연속 점수로 받거나** 반복 샘플
  평균을 쓴다
- **근거가 중복되면 무너진다.** "Python 5년"이 두 군데 적혀 있으면 하나를 지워도 점수가
  안 내려가고, 정당한 근거가 장식으로 찍힌다 → 소거를 span 단위가 아니라 **같은 뜻끼리
  묶은 단위**로 해야 한다
- 심사위원이 비결정적이면 노이즈가 기여도를 삼킨다. temperature=0 필수, 남는 분산은
  플라시보 3회로 추정해 `tau`에 반영

## 아이디어 3 — 등수 뒤집기 최소 편집

### 무엇인가

**"왜 3등인가"에 절대 점수가 아니라 인접 순위와의 차이로 답한다.**

각 지원자마다 **바로 위 순위를 넘어서는 데 필요한 최소 사실 집합**을 계산해 한 문장으로
낸다.

> 이 지원자는 **「컨테이너 운영 경험」 1건만 더 있었으면 2위**였습니다
> (현재 격차 4.2점, 해당 항목 배점 6점).
> 반대로 **「팀 리드 경험」이 빠졌다면 5위**로 내려갑니다.

**LLM을 한 번도 부르지 않는다.** 축별 점수 벡터가 이미 있으므로, 항목을 하나씩 켜고 끄며
총점을 다시 계산해 인접 순위를 넘기는 최소 부분집합을 찾으면 된다. 항목이 20개 이하면
완전 탐색이고, 넘으면 배점 내림차순 그리디다.

여기에 두 가지를 덧붙인다.

**(a) 동점권** — 점수 차가 임계값 미만이면 순위를 확정하지 않고 같은 밴드로 묶는다.

```
1위권: A (82.4) · B (81.9)   ← 구분 불가
3위:   C (71.0)
```

**(b) 게이트 항목 분리** — 게이트에서 이미 탈락한 지원자에게 "이것만 있으면 됩니다"는
거짓말이다. 게이트 항목은 최소 편집에서 **빼고 별도 문단**으로 적는다.

### 어디서 왔나

세 갈래가 같은 곳을 가리켰다.

1. **대조 설명 연구** — *"왜 A인가"보다 "왜 B가 아니라 A인가"*가 인간 수용성에서 우월하다.
   중요한 단서 하나: 대조 상대를 **아무거나 잡으면 효과가 없다.** 사람이 실제로 헷갈릴
   상대여야 한다 → 랭킹에서 그건 **인접 순위**다
2. **추천시스템의 쌍별 반사실** — "두 항목의 순위를 뒤집는 데 필요한 최소 프로필 항목
   집합"을 지표로 정의한 연구가 이미 있다(MPRR)
3. **감별진단의 배제 서술** — 임상은 진단을 내릴 때 **경합 가설을 왜 배제했는지**를
   같이 쓴다. DSM-5의 거의 모든 진단 기준 마지막 항목이 "~로 더 잘 설명되지 않을 것"이다

동점권의 근거는 랭킹 안정성 실측이다 — LLM 리더보드에서 **1% 미만의 조작으로 1위가
바뀐다**는 보고가 있다. 0.4점 차이로 1위와 2위를 확정하는 건 **거짓 정밀도**다.

### 왜 참신한가

우리 출력의 **불일치**를 정확히 짚는다. 결과는 **순위**인데 근거는 **개별 카드**로만 나온다.
3등 카드를 아무리 자세히 읽어도 **왜 2등이 아닌지는 안 나온다.**

그리고 이게 채용담당자가 실제로 던지는 질문이다. "이 사람 몇 점이에요?"가 아니라
"얘가 왜 쟤보다 위예요?"다.

**비용이 0이고 결정적이라는 게 결정적이다.** 앞의 두 아이디어는 LLM 호출을 늘리는데,
이건 이미 가진 숫자를 다시 조립하기만 한다. 그래서 **"LLM 근거는 점수를 만든 이유가
아니다"라는 문제 자체를 우회한다** — 계산이 곧 이유이기 때문이다.

부수적으로, 우리 목업 구성(완벽 2 / 부분 3 / 미스 1)에서 **완벽 매칭 2명을 가르는 진짜
이유**가 여기서 자동으로 튀어나온다.

### 비용

**추가 LLM 호출 0회.** 순수 계산. 구현 1~2시간.

### 이 아이디어가 틀리는 조건

- **점수 함수가 비단조·비가산이면 최소 편집이 유일하지 않다.** 여러 개 중 하나를 골라
  보여주는 순간, 어느 걸 골랐는지는 출력만 봐서 감사할 수 없다(반사실 설명의 체리피킹은
  이론적으로 탐지 불가능하다는 증명이 있다) → **탐색 규칙을 코드 상수로 고정하고 화면
  하단에 그 규칙을 적는 것**이 유일한 방어다
- **격차가 크면 문장이 무의미해진다.** 미스매칭 지원자는 최소 편집 집합이 커진다 →
  항목 3개를 넘으면 나열하지 말고 **"구조적 미달"**로 표기한다
- **지원자에게 노출하면 이력서 gaming 유인**이 된다 → 담당자 화면 전용으로 묶는다
- 동점권에 4~5명이 들어가면 도구가 무용해 보인다. 공고당 6명뿐이라 실제 위험이다 →
  밴드는 **정렬을 바꾸지 않고 배지로만** 표시한다

## 셋을 쌓는 순서

의존 관계가 있다.

```
3. 등수 뒤집기   ← 비용 0, 즉시 구현. 먼저 넣는다
       ↓
1. 판단유탈 대장 ← 추출 1회. 커버리지 지표가 생긴다
       ↓
2. 소거 재채점   ← 가장 비싸다. 표본으로만. 앞의 둘이 놓친 것의 마지막 방어선
```

**3 → 1 → 2 순으로 넣고, 예산이 모자라면 2를 표본에서 더 줄인다.**

## 뽑지 않은 것 (이유와 함께)

| 후보 | 왜 안 뽑았나 |
|---|---|
| **플라시보 배지 감사** — 이력서 내용은 그대로 두고 이름·소속·무의미한 배지만 바꿔 점수가 흔들리는지 검사 | **강력하고 아깝다.** 채용 도메인에서는 그대로 차별 감사가 된다. 다만 아이디어 2와 같은 계열(개입 후 재채점)이라 셋에 넣으면 축이 겹친다. **시간이 남으면 이걸 넣는다** |
| **문장 ID enum 강제** — 이력서를 문장 단위로 쪼개 번호를 붙이고, 인용을 그 번호로만 받게 해 존재하지 않는 인용을 문법 차원에서 봉쇄 | 추가 비용 0이고 우아하다. 그런데 이미 채택한 "문자열 대조"와 목적이 같다(사전 봉쇄 vs 사후 검사). **개선안이지 새 아이디어가 아니다** → step6에 구현 방식으로 흡수 |
| **반증 칸 의무화 + 추천 숨김** — 축마다 반박 증거를 나란히 쓰게 하고, 순위를 감춘 채 증거표만 먼저 보여주는 모드 | 과신을 73.9% → 53.3%로 낮춘 통제 실험(N=302)이 있어 근거가 강하다. 다만 **완벽 매칭 지원자에게는 반증이 실제로 없어서** LLM이 억지로 지어낸다. 아이디어 1의 `배척` 태그가 같은 일을 더 싸게 한다 |
| **적합도 / 증거 확실성 2축 분리 (GRADE)** | 우리 `evidence_grade`(E2/E1/E0)와 축이 겹쳐 보인다. 우리 건 **공고 조건의 근거 수준**이고 GRADE식은 **지원자 증거의 확실성**이라 실은 다른 축이지만, 설명이 헷갈린다 → 나중에 |
| **범위 제한 이의신청** — 사실 축(연차·자격증·파싱 결과)만 이의 가능, 판단 축은 불가 | 체조 심판의 inquiry 규칙에서 왔고 발상이 좋다. **공고가 이미지라서 파싱 오류가 실재 리스크**라 겨냥이 정확하다. 다만 24시간 안에 정정-재실행 루프까지 만들 여유가 없다 → README 아키텍처 절 |
| **절사평균** (최고·최저 제외) | **명시적으로 반대한다.** 절사평균은 담합 억제 장치이지 정확도 장치가 아니다. 우리 심사위원은 같은 모델의 복수 호출이라 **오차가 독립이 아니다.** 상관된 편향에 절사를 걸면 분산만 줄고 편향은 남아, "여러 명이 합의했다"는 **잘못된 안정감**만 준다 |

## 주의 — 놓치면 안 되는 것 하나

**형식 준수는 근거 신뢰도가 아니다.**

인용 실재율을 측정한 연구에서, **어떤 모델도 0.475를 넘지 못했고** 어떤 모델은 제약을
강하게 걸자 0.235에서 0.019로 무너졌다. 그런데 **그동안에도 출력 형식은 계속 규격을
지켰다.**

우리 파이프라인에서 이게 어디에 걸리는가 — JSON 스키마를 통과했다는 사실, 검산 G1~G5를
통과했다는 사실은 **"인용한 문장이 존재한다"만 보증한다.** "그 문장이 그 판정을 지지한다"는
전혀 보증하지 않는다.

**그래서 UI에서 두 지표를 반드시 분리해 표시한다.**

| 지표 | 무엇을 보증하나 | 어디서 나오나 |
|---|---|---|
| **인용 유효성** | 그 문장이 이력서에 실재한다 | 검산 G2 (문자열 대조) |
| **근거 충실도** | 그 문장이 점수를 만들었다 | 아이디어 2 (소거 재채점) |

전자가 100%여도 후자는 0일 수 있다. **둘을 한 배지로 합치면 그 순간 거짓말이 된다.**
