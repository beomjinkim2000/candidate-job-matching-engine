# 실행 — 평가자 머신에서 무엇이 일어나는가

> README「실행 방법」절의 원재료다. 이 문서는 README가 아니고, README를 대신하지도 않는다.

## 치는 명령

| | 명령 | 비고 |
|---|---|---|
| macOS | `python3 run.py` 또는 `start.command` 더블클릭 | |
| Windows | `python run.py` 또는 `start.bat` 더블클릭 | |

옵션은 넷뿐이다. `--port 8080` · `--no-browser` · `--with-ocr` · `--no-ocr`.

## 안에서 일어나는 일 (순서)

1. **파이썬 버전 확인.** 3.11 미만이면 무엇을 깔아야 하는지 적고 멈춘다.
   역추적(traceback)을 보여 주지 않는다 — 평가자가 읽어야 할 건 원인이지 스택이 아니다
2. **의존성 확인.** 하나라도 없으면 설치한다. 목록의 정본은 `pyproject.toml`의
   `[project].dependencies`이고, `run.py`가 `tomllib`으로 그걸 읽는다.
   **베껴 두지 않았다** — 베끼면 어긋나고, 어긋난 쪽이 실행 경로다
3. **키.** `.env`에 `OPENAI_API_KEY`가 있으면 아무 말 없이 지나간다. 없으면 받아서 쓴다
4. **데이터 점검.** 무엇이 되고 무엇이 안 되는지 **서버를 띄우기 전에** 적는다 (아래 §3)
5. **OCR.** 필요할 때만 받는다 (아래 §2)
6. **서버.** `127.0.0.1`에만 바인딩하고, **응답이 온 뒤에** 브라우저를 연다

## §1. 왜 `.venv`를 우리가 만드는가

최근 맥·리눅스의 시스템 파이썬은 `pip install`을 **거부한다**
(PEP 668, `externally-managed-environment`). 홈브루 파이썬도 그렇다. 그래서
격리 환경 밖이면 `run.py`가 저장소 안에 `.venv`를 만들고, 거기 설치하고,
**그 파이썬으로 자기 자신을 다시 실행한다.**

이미 완성된 `.venv`가 있으면 pip을 아예 부르지 않고 곧장 넘어간다.
「already satisfied」를 확인하자고 네트워크를 타면, 망이 막힌 환경에서 그게 실패로 돌아온다.

재실행에 `os.execv`를 쓰지 않았다. 윈도우에는 진짜 exec이 없어 콘솔 소유권과 Ctrl+C
처리가 어긋난다. `subprocess`는 양쪽에서 같게 돈다.

## §2. OCR은 기본으로 받지 않는다

PaddleOCR과 paddlepaddle은 휠만 수백 MB이고, 첫 실행에 모델 가중치를 또 받는다.
그런데 **랭킹을 보는 데는 OCR이 한 톨도 필요 없다** — 파싱 결과(`requirements.json`)와
목업 이력서가 저장소에 있어 채점이 그대로 재현된다.

받는 경우는 둘뿐이다.

1. `data/postings/<공고>/`에 이미지가 있는데 `ocr.json`이 없을 때.
   **사용자가 이미지를 직접 넣었다는 뜻**이다. 그때만 묻는다
2. `--with-ocr`로 명시했을 때

설치에 성공하면 모델 가중치까지 미리 받는다. 안 그러면 첫 파싱 요청이 브라우저에서
몇 분 동안 아무 말 없이 멈춰 보이고, 그 침묵은 「고장」으로 읽힌다.

**설치가 실패해도 서버는 뜬다.** 윈도우에서 paddlepaddle 휠이 없을 수 있는데,
그것 때문에 채점까지 못 하게 만들 이유가 없다. 못 쓰게 되는 것은 파싱 확인 화면 하나다.

## §3. 파싱 확인 화면이 평가자 머신에서 비는 이유

공고 이미지(`img_*.png`)와 그 전사본(`ocr.json`·`trace.json`·`header_roles.json`)은
**공고 본문 그 자체**라 저장소에 넣지 않는다 (`docs/LEGAL_ARCHITECTURE.md`,
과제 CRITICAL의 원문 복붙 금지). 그래서 평가자 머신에는 그림이 없고, 근거를 클릭해도
네모를 그릴 바탕이 없다.

**조용히 비우지 않는다.** 두 층에서 말한다.

- **서버를 띄우기 전** — `run.py`의 데이터 점검이 공고별로 「이미지 0장 · OCR 없음」을
  적고, 사유와 복구 방법(이미지를 놓으면 파싱부터 돌릴 수 있다)을 함께 적는다
- **요청 시점** — `GET /image/{id}`는 404, `GET /trace/{id}`는 409를 사유와 함께 준다
  (`src/matching/api/server.py`). 빈 응답을 200으로 주지 않는다

평가자 머신에서 실제로 갈리는 것:

| | 되나 | 왜 |
|---|---|---|
| 채점 · 랭킹 · 근거 | 된다 | `requirements.json` · `data/resumes/**`가 저장소에 있다 |
| 파싱 확인 화면(이미지 + 좌표 박스) | 안 된다 | 이미지도 `ocr.json`도 없다 |
| 새 공고 이미지를 넣고 직접 파싱 | 된다 | 그때만 OCR을 받는다 |

## §4. 키를 다루는 방식

- 입력은 `getpass`다. 화면에 안 보이고 셸 히스토리에도 안 남는다
- **저장 뒤에도 아무 조각도 찍지 않는다.** 뒤 네 자리도 안 찍는다.
  화면 캡처·터미널 로그·화면 공유에 조각이 남는 쪽이 더 비싸다
- `getpass`에는 **무에코 입력을 못 만들면 경고만 하고 그냥 받는 폴백**이 있다.
  그 폴백은 키를 화면에 찍는다. 경고를 예외로 승격시켜 그 경로를 끊었고,
  터미널이 아니면 아예 묻지 않는다
- 쓰기 전에 `git check-ignore`로 `.env`가 무시 목록에 걸리는지 본다. 안 걸리면 **저장하지
  않고 멈춘다.** 저장소가 아니면(zip으로 받은 경우) 커밋될 곳이 없으므로 그대로 진행한다 —
  「확인 못 함」과 「걸리지 않음」을 같게 취급하지 않는다
- 파일은 `os.open(..., 0o600)`으로 **만들 때** 권한을 준다. 만들고 나서 `chmod`하면
  그 사이에 키가 열린 파일로 잠깐 존재한다
- 기존 `.env`를 통째로 덮어쓰지 않는다. `OPENAI_API_KEY` 줄만 갈아 끼운다

## §5. 윈도우에서 위험하다고 본 지점

실제로 윈도우에서 돌려 보지는 못했다. 아래는 코드를 줄 단위로 훑어 고른 것이고,
각각 어떻게 처리했는지를 적는다.

| 지점 | 무엇이 문제인가 | 처리 |
|---|---|---|
| `SO_REUSEADDR`로 빈 포트 확인 | 윈도우에서 이 옵션은 **「쓰는 중인 포트에도 붙게 해 준다」**는 뜻이다. 리눅스·맥과 의미가 정반대라, 걸어 두면 점검이 항상 통과한다 | 옵션을 **걸지 않고** bind만 시도한다 |
| 콘솔 인코딩 | 파이프·리다이렉트에서는 로캘 인코딩(영문 윈도우면 cp1252)이 잡혀 한글에 `UnicodeEncodeError`가 난다 | 진짜 콘솔이면 `errors="replace"`만, 리다이렉트면 utf-8로 바꾼다. 콘솔일 때 utf-8을 강제하지 **않는다** — 파이썬이 이미 `WriteConsoleW`로 쓰므로 코드페이지와 무관하다 |
| 이모지·박스문자 | 기본 콘솔 글꼴에서 깨진다 | 쓰지 않는다. 구분선은 `-` 반복이다 |
| `.bat`의 줄바꿈 | LF만 있는 배치 파일에서 괄호 블록과 마지막 줄이 잘리는 사례가 있다 | `.gitattributes`로 `*.bat text eol=crlf`를 못박았다 (`*.command`·`*.sh`는 반대로 `eol=lf` — CRLF면 `bad interpreter: /bin/sh^M`) |
| `.bat` 안의 한글 | cmd는 배치 파일을 OEM 코드페이지로 읽는다 | `start.bat`은 **ASCII만** 쓴다. 설명은 이 문서와 `run.py`에 있다 |
| `python`이 Microsoft Store 스텁 | 스토어 창만 뜨고 아무것도 안 돈다 | `start.bat`이 `py` 런처를 먼저 찾는다 (`py -3`은 설치된 최신 3.x를 고른다) |
| `os.chmod(path, 0o600)` | 윈도우에는 POSIX 권한이 없다. 읽기전용 플래그 하나로만 번역되어 「소유자만 읽기」가 안 된다 | 예외는 안 나므로 실행은 계속하되, 저장 직후 **그 사실을 알린다**(공용 PC면 다 쓰고 지우라고) |
| 재실행에 `os.execv` | 윈도우에 진짜 exec이 없어 콘솔 소유권·Ctrl+C가 어긋난다 | `subprocess.run`으로 통일했다 |
| `getpass` 폴백 | 폴백이 키를 화면에 찍는다 | 경고를 예외로 승격, 비-TTY면 거부 |
| paddlepaddle 휠 없음 | 윈도우·특정 파이썬 버전 조합에서 설치가 깨질 수 있다 | 선택 그룹으로 분리했고, 실패해도 **서버는 그대로 뜬다** |
| `webbrowser.open` 타이밍 | 포트만 잡고 열면 빈 화면이 뜬다 | 실제로 200이 올 때까지 폴링한 뒤 연다. `http_proxy`가 걸려 있어도 `127.0.0.1`은 프록시를 태우지 않는다 |

Ctrl+C로 배치를 멈추면 cmd가 `Terminate batch job (Y/N)?`을 묻는다. 이건 cmd의 동작이고
서버는 이미 내려간 뒤다.

## §6. 실제로 확인한 것 (macOS 15 / Apple Silicon)

- 파이썬 3.9.6(맥 기본 `python3`)으로 실행 → 역추적 없이 안내만 찍고 종료(코드 1)
- **저장소를 새로 받은 상태를 흉내** — 추적 파일만 꺼낸 디렉터리에서 홈브루 3.14로 실행.
  `.venv`가 없으므로 만들고, `pyproject.toml`에서 읽은 7개를 설치하고, 그 파이썬으로
  다시 실행하고, 데이터 점검이 「파싱 확인 화면: 불가」와 사유를 찍고, 서버가 떠서
  `GET /` = 200
- `start.command` 더블클릭 경로 → 3.14를 고르고 → 완성된 `.venv`를 찾아 **pip을 부르지
  않고** 넘어가 → `GET /` = 200
- `GET /postings` = 200 (공고 2건)
- 8123을 쓰는 중일 때 `pick_port(8123)` → 8124
- 프록시 환경변수가 걸린 상태에서 브라우저 열기 → `127.0.0.1`을 직접 열었고,
  서버가 1.5초 늦게 떠도 기다렸다 열었다. 죽은 포트에서는 안내만 찍고 열지 않았다
- SIGINT → 부모·자식 둘 다 내려갔고 남는 프로세스가 없었다
- 키 경로는 **임시 디렉터리에서** 시험했다(실제 `.env`는 건드리지 않았다):
  무시 목록에 없으면 중단 · 있으면 저장 후 권한 `0o600` · 다른 줄 보존 ·
  비-TTY에서 입력 거부

윈도우는 실행 환경이 없어 확인하지 못했다. §5가 그 대신이다.
