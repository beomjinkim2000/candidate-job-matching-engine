## 2. 이미지 확보 분기 — 시각이 박힌 대안

**요구 ①(사람인 API로 크롤링)이 아직 발급 안 된 access-key 위에 서 있다.**
승인 메일이 언제 오는지 우리가 모른다. 그래서 **기다리지 않는 경로**를 시각과 함께 정한다.

```
2026-09-01 06:00 KST — 판단 시점
   │
   ├─ access-key 있음 ──▶ 경로 A. SaraminSource로 list_postings() 실호출
   │                        data/.saramin_quota.json에 200 응답 기록 → req1 = "verified"
   │
   └─ 없음 ────────────▶ 경로 B. 아래
```

### 경로 B — 키 없이 진행한다

1. **공고 이미지는 이미 확보돼 있다.** 2026-09-01 02:5x에 대상 공고 2건이 확정됐고
   (KT `rec_idx=54832105` · 넥슨 `rec_idx=54828914`, `Plans.md` Phase 1.5)
   이미지는 브라우저에서 직접 저장해 `data/postings/{id}/img_*.png`에 둔다.
   **API가 없어도 파이프라인 전체가 돈다** — 요구 ②~⑧은 영향을 받지 않는다
2. `SaraminSource`는 **코드로만 존재**한다. `source_kind`가 `local`로 결과에 실리고,
   UI와 CLI 출력에 **「API 미검증 — 이미지 수동 확보」**가 표시된다. 조용히 넘어가지 않는다
3. `index.json` step 2의 `requirement_status.req1_api_crawl`이 `"unverified"`로 남는다.
   **`status: completed`가 이걸 덮지 않는다** (`step2.md` status 규칙)
4. **`docs/`에 요구 ① 미충족을 명시한다.** 숨기면 그게 더 큰 감점이다

### 경로 B에서 잃는 것 — 적어둔다

- 요구 ①(「API로 크롤링해서 확보한다」)이 **코드까지만 충족**된다. 실호출 증거가 없다
- clone한 사람이 「이 사람이 API를 실제로 썼다」를 확인할 파일이 **없다** —
  이미지는 `.gitignore`, 본문 저장 금지, 공고 ID·URL도 금지이기 때문이다.
  **그래서 `data/postings/{id}/provenance.json`을 만든다**(아래 §3). 이게 유일한 답이다

### 키가 06:00 이후에 오면 — 상한이 있다

| 도착 시각 | 무엇을 한다 |
|---|---|
| 06:00 ~ **16:00** | `SaraminSource.list_postings()`를 **1회만** 부르고 응답 기록을 남긴다 (30분). 이미지는 이미 있으므로 다시 받지 않는다. `req1_api_crawl`을 `"verified"`로 올린다. **파이프라인을 다시 돌리지 않는다** — 바뀌는 것은 메타데이터 한 줄뿐이다 |
| **16:00 이후** | **아무것도 하지 않는다.** `unverified`인 채로 제출한다 |

**16:00이 상한인 이유**: 17:00이 push 마감이고, 그 1시간은 키 누출 검사·클론 후 실행
확인에 쓴다. 마감 40분 전에 새 네트워크 호출을 넣어 얻는 것(메타데이터 한 줄)보다
**그때 뭔가 깨졌을 때 잃는 것**이 훨씬 크다.

## 3. `provenance.json` — 「어디서 왔는가」의 유일한 증거

이미지도 본문도 ID도 레포에 못 남기는데, 심사위원은 출처를 확인해야 한다. 남길 수 있는
것만 남긴다.

```json
{
  "posting_id": "kt-nw",
  "source_kind": "local",
  "acquired_at": "2026-09-01T03:00:00+09:00",
  "target_position": "NW인프라운용",
  "image_sha256": ["<64hex>"],
  "image_size": [[1131, 4200]],
  "ocr_engine": "paddle",
  "ocr_sha256": "<64hex>",
  "api_verified": false,
  "api_verified_at": null
}
```

- **해시만 남긴다.** 원문도 URL도 아니다. 「우리가 파싱한 그 이미지」의 동일성만 증명한다
- 이미지를 가진 사람은 해시를 대조해 **같은 파일인지 확인**할 수 있다
- `requirements.json`의 `ocr_sha256`과 여기 값이 일치해야 한다 — 안 맞으면 조건이 다른
  OCR 결과에서 나온 것이다

### 레포에 남는 것과 안 남는 것 — 경계는 「원문이냐 산출물이냐」다

| | 커밋 | 왜 |
|---|---|---|
| `img_*.png` | ✗ | 공고 본문 (그림) |
| `ocr.json` | ✗ | 공고 본문 (글자). **같은 것이다** — 그림과 글자를 다르게 취급하지 않는다 |
| `provenance.json` | ✅ | 해시. 원문이 아니다 |
| `requirements.json` | ✅ | **구조화된 조건.** `src/CLAUDE.md`가 「남긴다」고 명시한 것 |
| `data/resumes/**` · `data/runs/**` | ✅ | 우리가 만든 것 |

`ocr.json`을 커밋하면 이미지를 뺀 의미가 사라진다 — **오히려 검색 가능해져서 더 나쁘다.**
무시 패턴과 판단 근거는 `step0.md`에 있다.

## 4. 이 문서가 틀리는 조건

- 과제 수령 시각 추정(2026-08-31 18:00)이 틀리면 **모든 행이 이동한다.**
  **확인 시각: 2026-09-01 05:00, 담당: 리드** — §1을 실제 소요로 개정하는 그 자리에서
  사용자에게 **과제 메일 수신 시각을 한 번 묻고** §0을 고친 뒤 나머지를 재계산한다.
  **05:00에 안 물으면 이 표는 추정 위에서 끝까지 간다.** 「알게 되면」은 시각이 아니다
- 「~시간」 추정은 이 프로젝트의 실측이 아니다. **step 0·1·2가 끝나는 05:00에 §1을 한 번
  고친다** — 실제 소요를 재서 나머지 행을 밀거나 당긴다. 고치는 시각을 안 박으면 이 표는
  07:00쯤 조용히 의미를 잃는다

## 5. 「나중에 고친다」의 시각 — 전부 여기 모아둔다

계획 문서 곳곳에 「실측으로 대체한다」·「다음에 고친다」가 흩어져 있다. **시각이 없으면
안 일어난다.** 전부 시각을 붙여 여기 모은다.

| 무엇 | 어디 | **언제** | 누가 |
|---|---|---|---|
| §1 시각표를 실제 소요로 개정 | 이 문서 §1 | **05:00** (step 0·1·2 직후) | 리드 |
| 화면의 「예상 호출 ~59회」를 실측으로 교체 | `step9.md` | **14:30** (step 13, 완주 후) | step 13 |
| `COST_BUDGET` §4 실측 채우기 | `docs/COST_BUDGET.md` | **14:30** | step 13 (13-A) |
| `unaddressed_rate` 실측 분포 기록 | `step12.md` | **13:30** (step 12 완료 시 `summary`) | step 12 |
| 장황함 **실측치 기록** (임계 10%는 고정. 안 고친다) | `step11.md` | **12:30** (step 11 완료 시 `summary`) | step 11 |
| 반복 안정성 σ 실측 → 배점 재검토 논의 | `step6.md` | **14:30** — 실측만 남긴다. **논의는 이번 24시간에 하지 않는다** | **step 13-B**. 지시는 `step13.md`의 「다음 사람이 할 일」 표 첫 행에 있다 |

**마지막 행이 중요하다.** 「판단 층 65점을 사실 층으로 옮기는 논의」는 문헌 검토를 다시
해야 하는 일이라 **오늘 안에 못 한다.** 그걸 「논의를 시작한다」로 열어두면 영원히 안
닫힌다. **오늘 하는 것은 σ를 재서 적는 것까지**이고, 그 숫자를 `docs/OPERATIONS.md`의
「다음 사람이 할 일」로 넘긴다.
