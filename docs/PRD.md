# PRD: 지원자–공고 매칭 스코어링 엔진

## 목표

**채용공고 이미지 한 장에서 지원자 랭킹까지 가되, 모든 점수가 「공고 그림의 어느 좌표에서
나온 조건인가」와 「이력서 원문의 어느 구간을 근거로 삼았는가」까지 되짚어지게 한다.**

「점수를 잘 매기는 문제」가 아니라 **「왜 그 점수인지 답할 수 있게 만드는 문제」**로 읽었다.
그래서 정확도보다 **근거의 추적 가능성**을 앞에 뒀고, 근거를 못 대는 점수는 아예 만들지
않는다.

## 사용자

| | 누구 | 무엇을 하나 |
|---|---|---|
| **주** | 채용 담당자 (고객사) | 조건 목록을 확인·승인하고, 랭킹과 근거를 읽는다 |
| **부** | 서비스 운영자 | 공고를 넣고 파싱이 제대로 됐는지 본다 |
| — | **지원자** | 이 제품을 직접 쓰지 않는다. **다만 결과의 대상이라 마스킹·차별 방지의 이유가 된다** |

승인 단계가 있는 이유가 첫 줄에 있다 — **채점 기준을 우리가 정하면 「남의 채용 기준을
대신 정한 것」**이 된다. 고객사가 확정해야 그 회사의 기준이 된다.

## 핵심 기능

1. **공고 이미지 → 조건 추출**
   OCR로 줄과 좌표를 읽고, 코드가 섹션·항목을 나눈 뒤 필수/우대를 판정한다.
   **조건마다 공고 그림 위의 픽셀 좌표가 붙는다.**
2. **조건 → 채점 기준 생성**
   채점 항목은 공고에서 나오고, 배점은 조건 개수에서 계산된다.
   판정 문구(1/3/5점)만 코드에 고정돼 있다.
3. **사람 승인** ⛔
   여기서 파이프라인이 실제로 멈춘다. 승인 없이는 채점 함수가 예외를 던진다.
4. **채점 → 0~100점 + 랭킹 + 근거**
   게이트·사실·판단 3층. 판단 층은 심사위원 2명이 독립 채점하고 평균을 낸다.
   항목마다 **이력서 원문의 어느 구간을 인용했는지**가 남는다.
5. **검산 게이트**
   결과를 내보내기 전에 매번 검사한다. 하나라도 걸리면 결과가 나가지 않는다.
   **설계는 G1~G7이고 실제로 도는 것은 6개다** — G6(판단유탈 대장)은 미구현.
   못 만든 것을 「돈다」고 적지 않는다.
6. **단일 진입점 + 화면**
   `run.py` 하나로 설치·키 입력·서버 실행·브라우저 열기까지. 화면에서 공고를 고르고
   조건을 승인하고 랭킹과 근거를 본다. 자기 공고 이미지와 이력서를 올릴 수도 있다.

## 성공 기준

| | 무엇 | 어떻게 확인 |
|---|---|---|
| 1 | 설계한 매칭 유형이 **점수로 갈린다** | 완벽↔부분 **32.74점** · 부분↔미스 **16.66점** |
| 2 | **직군이 코드에 없다** | 서로 다른 직군의 공고 2개에서 같은 코드로 각각 11개·19개 항목 생성 |
| 3 | 원문을 복붙하지 않았음이 **기계로 증명된다** | 검산 G4 — 좌표 없는 조건이 있으면 결과 차단 |
| 4 | 지어낸 인용이 **통과하지 못한다** | 검산 G2 — 인용을 원문에서 다시 잘라 저장 |
| 5 | 승인이 **형식이 아니다** | 승인 없이 채점 호출 시 예외 |

## MVP 제외 사항

| | 안 만드는 것 | 이유 |
|---|---|---|
| 1 | **고객사 push 경로**(프로덕션 데이터 수급) | 과제가 「실제로 구현하지 않으셔도 되고」라고 명시. 구현하면 **검증되지 않은 코드**가 제출물에 들어간다. 인터페이스만 둔다 |
| 2 | **사후 보정·학습 루프** | 원본을 적재하지 않기로 했으므로(ADR-011) 모델이 좋아질 경로도 같이 닫힌다. **정확도와 법적 안전성을 맞바꾼 것** |
| 3 | **가중치 조정 UI** | 열면 직군별로 배점을 조정하게 되고, 그게 곧 직군 하드코딩이다 (ADR-007) |
| 4 | 사용자 계정·권한 | 데모 범위 밖. 서버는 `127.0.0.1`에만 바인딩한다 |
| 5 | **조건부 조건 처리**(「남성의 경우, …」) | **미구현이고, 이건 제외가 아니라 한계다.** 지금 여성 지원자가 그 항목에서 만점을 받는 것은 고쳐서가 아니라 우연이다 |

## 디자인

- **다크 단일 테마.** 결과를 읽는 화면이라 대비를 우선하고 색을 아낀다
- **배지로 상태를 말한다** — 「데모 데이터」 · 「미승인」 · 「AI 초안 / 사람 확인함」.
  **조용히 지나가는 상태를 만들지 않는다**
- **근거는 클릭하면 원문 위치를 보여준다.** 점수 옆에 인용이 붙고, 조건은 공고 그림의
  좌표로 이어진다
- 진행 표시는 **아는 것만 보여준다.** 서버가 진행률을 안 주므로 「경과 시간으로 찍은
  추정」이라고 화면에 적는다
